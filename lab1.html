Lab 1: How my system connects to its cloud database

NOAH Glacier is an Ionic/Angular app. Its data lives in Supabase, a cloud PostgreSQL database. These are the steps I followed to connect the two.

How the pieces fit

Ionic/Angular app
   |  supabase-js  (Project URL + anon key)
   v
Supabase cloud:  Auth | REST API | Storage | Edge Functions
   |  Row Level Security checks every request
   v
PostgreSQL database

Steps

  1. Create the cloud project

    Sign in at supabase.com and choose New project. Pick a region close to your users and set a strong database password. Save the password, then wait until the project finishes setting up.

  2. Create the tables and the security rules

    Open SQL Editor, then paste and run schema.sql (tables) followed by policies.sql (Row Level Security). RLS decides which rows each signed-in user may read or change.

  3. Copy the two connection values

    Go to Project Settings, API and copy the Project URL and the anon public key.
    The service_role key bypasses all security. It must never be placed in the app or on GitHub.

  4. Install the client library

    npm install @supabase/supabase-js

  5. Store the values in the app's configuration

    // src/environments/environment.ts
export const environment = {
  supabaseUrl: 'https://YOUR-PROJECT-REF.supabase.co',
  supabaseAnonKey: 'YOUR-ANON-PUBLIC-KEY'
};

  6. Create one shared client

    I create it once inside AuthService, so every page reuses the same signed-in connection. 
    import { createClient } from '@supabase/supabase-js';

readonly supabase = createClient(
  environment.supabaseUrl,
  environment.supabaseAnonKey
);

  7. Read and write data

    Queries look like this. RLS makes the database return only the rows the current user is allowed to see. 
    const { data, error } = await this.auth.supabase
  .from('classes')
  .select('*')
  .order('created_at', { ascending: false });

  8. Sign users in

    const { data, error } = await this.supabase.auth
  .signInWithPassword({ email, password });
    After sign-in, supabase-js attaches the user's token to every request automatically.

  9. Add server-side logic with Edge Functions

    Work that must not run in the browser (grading a quiz, checking a QR code) runs in an Edge Function. 
    supabase login
supabase link --project-ref YOUR-PROJECT-REF
supabase secrets set QR_SIGNING_SECRET=a-long-random-value
supabase functions deploy manage-attendance-session
    The app calls it with this.supabase.functions.invoke('manage-attendance-session', { body }).

  10. Check that the connection works

    • Sign in and open a page that lists data. Rows should appear.
    • Sign in as a different user. That user should see different rows (RLS at work).
    • In the browser's Network tab, requests go to YOUR-PROJECT-REF.supabase.co.

Common problems

What you seeLikely causeFix
A query returns an empty list, no errorNo RLS policy allows this user to read the tableCheck the policies and make sure the user is signed in
401 or "permission denied"Wrong anon key, or not signed inRecopy the key from Project Settings, API
Edge Function blocked in the browser (CORS)The preflight request has no tokenLet the OPTIONS request through and verify the user inside the function
Edge Function says "Unknown action"The deployed function is older than the appRedeploy it with supabase functions deploy
